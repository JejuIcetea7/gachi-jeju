# 원본(raw) 데이터 명세

`data/raw/` 아래 원본 데이터를 구분하는 방법과 담긴 내용을 정리한다.
원본은 수정하지 않고 받은 그대로 둔다.
원본은 git에 올리지 않고 로컬에만 보관한다(`.gitignore`). 다운로드 목록 `data_go_kr/links.csv`만 git에 둔다.

## 1. 디렉터리 구조

```
data/raw/
├── jeju_datahub/            ← 제주데이터허브에서 받은 데이터 (hub_1 ~ hub_121)
└── data_go_kr/              ← 공공데이터포털 조사 대상 191건 (dgk_<data_id>)
    └── links.csv            ← 공공데이터포털 292건 목록과 제외 여부
```

## 2. 폴더 구분

### 2-1. `jeju_datahub/hub_N` (121개)

| 구분 | 폴더 | 개수 | 폴더 이름의 N |
| --- | --- | --- | --- |
| 번호 폴더 | `hub_1` ~ `hub_51` | 51 | 관광지 아이디(가이드 문서 목록의 번호) |
| 장소명 폴더 | `hub_52` ~ `hub_121` | 70 | 구분용 일련번호 (의미 없음) |

번호 폴더 구성
- `NNN-1.csv`: 조사자가 이동한 전체 좌표. 컬럼: 아이디, 위도, 경도, 고도
- `NNN-2.csv`: 정보(사진, 설명)를 등록한 지점만. 컬럼: 아이디, 위도, 경도, 고도, 장소명, 장소 설명, 이미지 파일명
- `제주무장애여행 데이터셋 가이드문서.hwp`: 51개 폴더 모두 같은 파일. 안에 아이디(001~051) → 관광지명 목록이 있다.
- `hub_14`(오설록)만 `-1.csv` 없이 `014-2.csv`만 있다.

장소명 폴더 구성
- `제주특별자치도_무장애여행정보_<장소명>.csv` (70개)
  - 50개: 컬럼 `위도, 경도, 장소명칭, 장소상세정보, 무장애관광정보, 추천코스여부, 데이터품질점검결과, 데이터기준일자`
  - 20개: 컬럼 `ID, lat, lon, title, Description, Image, Point, info, A, B, etc`
- `제주특별자치도_무장애여행정보_<장소명>.hwp`: 20개 (파일이 큼, Git LFS)

### 2-2. `data_go_kr/dgk_<data_id>` (191개)

- 폴더 이름의 숫자는 공공데이터포털 데이터 ID이다. 상세 주소는 `https://www.data.go.kr/data/<data_id>/fileData.do`.
- 폴더마다 원본 파일과 `meta.json`(제목, URL, 그룹, 받은 곳, 파일 목록)이 있다.
- `meta.json`의 `downloaded_from`으로 받은 곳을 구분한다. 허브에서 받은 것은 `hub_id`, `provider_url`도 있다.

| 그룹(`links.csv`의 `group`) | 건수 | 받은 곳 | 파일 | 내용 |
| --- | --- | --- | --- | --- |
| B주변정보 | 50 | 공공데이터포털 | CSV | 관광지 주변 시설. 컬럼: 관광지명, 주변시설종류, 명칭, 반경, 주소, 연락처, 이용정보 |
| D관광정보 | 49 | 제주데이터허브 | HWP | 장소 개요, 주소, 주차장, 화장실, 코스, 휴무일 등 기본 정보와 지점별 사진, 장애 유형별 추천 여부. 허브의 파일명은 `..._무장애여행일반정보.hwp` |
| D코스 · 그 외 | 92 | 제주데이터허브 | CSV | 위치정보 50개: 순서, 위도, 경도, 구분, 설명, 포인트, 상세정보, 전체코스여부, 추천코스여부. 주변시설 42개: 구분, 명칭, 거리(km), 주소, 전화번호, 휠체어 진입, 장애인 화장실 |

## 3. `links.csv`

공공데이터포털 검색 결과 292건(고유 ID 기준)의 목록이다.

| 컬럼 | 뜻 |
| --- | --- |
| `data_id` | 공공데이터포털 데이터 ID |
| `title`, `url` | 제목, 상세 페이지 주소 |
| `group` | A번호 / B주변정보 / D관광정보 / D코스 / 그 외 (제목 형태로 나눈 구분) |
| `provide_type` | 공공데이터포털(파일 직접 제공) / 허브연결(제공처 URL로 연결) |
| `file_ext` | 목록에 표시된 파일 형식 |
| `status` | `excluded`: 이미 가진 데이터라 받지 않음(101건), `target`: 조사 대상(191건) |
| `local_folder` | `excluded`인 경우 대응하는 `jeju_datahub` 폴더 |
| `reason` | 제외 사유 |

## 4. 중복 관계 (조사 결과)

| 공공데이터포털 | 로컬 대응 | 근거 | 건수 |
| --- | --- | --- | --- |
| A번호 중 허브 연결 | `hub_1` ~ `hub_51` | 번호와 장소명이 가이드 목록과 일치. 허브 미리보기와 `-1.csv`의 행이 모두 일치(`hub_14`는 `-2.csv` 기준) | 51 |
| A번호 중 직접 제공 | 장소명 폴더의 컬럼이 `위도, 경도, 장소명칭, ...`인 CSV | 장소와 컬럼이 같다. 동문시장은 행이 완전히 같고, 북촌마을해안길은 1칸이 다르다. 나머지 48건은 내용 대조하지 않았다. | 50 |

- `links.csv`에서 위 101건은 `excluded`로 두었고 `dgk_` 폴더가 없다.
- 번호가 같아도 시리즈가 다르면 다른 데이터이다. 예: 허브 연결 `_2.더마파크`와 직접 제공 `_02-북촌마을해안길`.
- 장소명 폴더에만 있고 공공데이터포털 목록에 없는 장소가 25곳 있다. 예: 아르떼뮤지엄, 빛의벙커, 무민랜드.

## 5. 주의

- CSV는 모두 UTF-8이 아니라 cp949(EUC-KR)로 읽힌다(`jeju_datahub` 171개, `data_go_kr` 142개 확인). UTF-8로 열면 글자가 깨진다.
- 공공데이터포털 직접 제공 파일은 파일명에 `_20201222`, `_20201230`처럼 데이터 기준일이 붙어 있다. 포털의 수정일과 다를 수 있다.
- 허브 제목과 공공데이터포털 제목이 다른 경우가 있다. 예: `..._무장애여행관광정보`(포털) ↔ `..._무장애여행일반정보`(허브), `한림공원`(제목) ↔ `한담공원`(CSV 파일명).
- HWP는 Git LFS 대상이다(`.gitattributes`). `git lfs pull` 전에는 130바이트 정도의 포인터 파일이다.
- `data_go_kr`의 HWP 49개와 장소명 폴더의 HWP 20개는 내용을 열어 확인하지 않았다. `D관광정보`의 내용 설명은 허브 페이지의 설명과 미리보기 표(1건)를 근거로 한 것이다.

## 6. 아직 확인하지 않은 것

- 장소명 폴더 CSV와 직접 제공 A번호 50건 중 48건의 내용 대조
- 번호 폴더 `-2.csv`와 허브 데이터의 대조
- 허브 연결 141건과 로컬 장소명 폴더의 겹침 (장소명은 겹치지 않으나 좌표 대조는 하지 않음. `이호테우해변과내도동알작지` 1건은 이름이 일부 겹침)
