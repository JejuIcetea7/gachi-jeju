# 여행 일정 PDF 이메일 발송

‘여행 지도와 일정’ 제목 오른쪽의 ‘이메일로 받기’를 누르고
받는 주소를 입력한 뒤 ‘PDF 보내기’를 누릅니다.
현재 일정의 전체 날짜를 기존 PDF 생성기로 문서화하여 첨부합니다.
화면에서 선택한 일차만 보내거나 아직 적용하지 않은 옵션을 섞지 않습니다.

────────────────────────────────────────

## 1. 화면 동작

이메일 입력 창을 열면 주소 입력란에 초점을 맞춥니다.
빈 주소와 잘못된 주소는 전송 전에 차단하고 서버에서도 다시 검사합니다.
받는 주소는 대화 저장 데이터에 포함하지 않습니다.

발송 요청 중에는 중복 제출과 입력 창 닫기를 막습니다.
일정 교체나 화면 종료로 응답 대기를 중단해도
이미 시작한 메일 전송이 취소됐다고 표시하지 않습니다.

프론트엔드 응답 대기 제한은 45초입니다.
네트워크 오류나 제한 시간 초과로 접수 결과를 확인하지 못하면
수신함과 스팸함을 먼저 확인하도록 안내하며 자동 재시도하지 않습니다.
메일 서버의 접수 확인은 수신함 도착을 보장하지 않습니다.

발송 설정이 없으면 PDF 생성 전에 미설정 안내를 반환합니다.
기존 지도·일정과 PDF 다운로드는 계속 사용할 수 있습니다.

────────────────────────────────────────

## 2. API

| 항목 | 내용 |
|---|---|
| 백엔드 | POST /itineraries/email |
| 개발 프록시 | POST /api/itineraries/email |
| 요청 | PDF 다운로드의 options·plan·warnings·transit_routes와 recipient |
| 정상 응답 | HTTP 200, status=accepted, duplicate, message |
| 입력·첨부 오류 | 400 invalid_request, 413 email_attachment_too_large |
| 설정·처리 제한 | 503 email_not_configured 또는 email_busy, 429 email_rate_limited |
| 기존 요청 처리 중 | 409 email_in_progress |
| 접수 여부 미확인 | 502 또는 재요청 시 409 email_delivery_unknown |

duplicate=true는 최근의 동일한 접수 결과를 재사용했음을 뜻합니다.
대화 기록, 지도 도로선과 모델 메타데이터는 요청에 포함하지 않습니다.
접수 결과와 발송 처리 오류 응답에는
Cache-Control: private, no-store를 지정합니다.

────────────────────────────────────────

## 3. 중복 제출과 처리 제한

같은 수신자와 같은 일정의 접수 결과를 10분 동안 재사용합니다.
접수 여부가 불명확한 동일 요청도 기록 유지 중에는 다시 제출하지 않습니다.
처리 중인 기록은 시간이 지났다는 이유만으로 제거하지 않습니다.

같은 수신자에게 다른 일정을 보내려면 직전 처리 종료 후 60초가 필요합니다.
동시에 두 요청까지 처리하며 최근 기록은 최대 256개입니다.
PDF 준비 실패와 명시적인 SMTP 거부는 예약을 해제합니다.
자동 재시도는 수행하지 않습니다.

기록은 서버 프로세스 메모리에만 보관합니다.
서버 재시작 시 초기화되며 여러 서버 프로세스 사이에서 공유하지 않습니다.
현재 단일 프로세스 실행을 기준으로 합니다.

────────────────────────────────────────

## 4. 발송 서버 설정

발송 계정이 준비되면 프로젝트 설정 로더가 읽는 값으로 지정합니다.
비밀번호와 실제 계정 정보는 Git이나 프론트엔드에 넣지 않습니다.

| 변수 | 내용 |
|---|---|
| ITINERARY_EMAIL_ENABLED | 발송을 활성화할 때 true. 기본은 비활성화 |
| ITINERARY_SMTP_HOST | SMTP 서버 호스트 |
| ITINERARY_SMTP_PORT | STARTTLS 기본 587, SSL 기본 465 |
| ITINERARY_SMTP_SECURITY | starttls 또는 ssl |
| ITINERARY_SMTP_USERNAME | SMTP 인증 계정 |
| ITINERARY_SMTP_PASSWORD | SMTP 비밀번호 또는 서비스에서 발급한 자격 증명 |
| ITINERARY_EMAIL_FROM | 발송 서버에서 허용한 발신 이메일 주소 |

TLS 인증서 검증을 유지하고 평문 연결에서는 인증하지 않습니다.
SMTP 네트워크 작업별 제한 시간은 10초이며 전체 처리 시간 제한은 아닙니다.
첨부 PDF의 최대 크기는 10MiB입니다.

## 5. 검증 상태

2026-11-18 기준입니다.

| 구분 | 확인 결과 |
|---|---|
| 백엔드 | 전체 Python 테스트 1,130개 통과 |
| 프론트엔드 | 이메일·PDF 통신 테스트 28개와 lint·build 통과 |
| 브라우저 | 입력 창·초점, 주소 검사, 미설정 안내, 기존 일정·다운로드 유지와 좁은 화면 배치를 사용자 확인 |
| 실제 메일 | 네이버 SMTP로 본인 주소 수신과 첨부 PDF 열림·내용 일치를 사용자 확인 |

자동 테스트는 SMTP를 모의 처리하며 실제 메일을 보내지 않습니다.
네이버 SMTP를 통한 실제 수신과 첨부 PDF 내용은 사용자가 별도로 확인했습니다.
