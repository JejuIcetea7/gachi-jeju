# 여행 조건 입력·출발지 선택 UI

검증일: 2026-11-09

## 1. 구현 범위

| 기능 | 구현 내용 |
|---|---|
| 출발지 선택 | 첫 화면에서 센터 출발, 장소 검색, 현재 위치 중 하나로 출발지를 정합니다. |
| 여행 조건 입력 | 여행 종류, 이동수단, 날짜·시간, 필수 이용 조건, 휴식 시간, 출발지 귀환 여부를 선택합니다. |
| 조건 요약·수정 | 입력 조건을 검사하고 요약합니다. ‘출발지 변경’을 누르면 첫 화면으로 돌아갑니다. |
| 추가 요청 | 요약 화면에서 요청을 입력하고 목록에 등록합니다. 요청당 최대 1,000자이며, Agent 응답은 아직 연결하지 않았습니다. |
| 새로고침 복원 | 현재 화면, 확정한 출발지, 여행 조건, 등록한 추가 요청을 같은 탭에서 복원합니다. |

**출발지 선택 방식**

| 방식 | 동작 |
|---|---|
| 센터에서 출발 | 설정한 센터 주소를 카카오 주소 검색으로 조회하여 이름·주소·좌표를 설정합니다. |
| 장소 검색 | 제주 지역의 후보를 최대 5개 표시합니다. 후보를 지도에서 확인한 뒤 확정합니다. |
| 현재 위치 사용 | 버튼을 눌렀을 때 기기 위치를 한 번 조회하고, 해당 좌표를 출발지로 설정합니다. |

센터 주소 설정값은 `제주특별자치도 제주시 첨단로 241`입니다.
저장된 출발지가 있으면 해당 장소를 복원합니다.

출발지가 확정되면 여행 종류를 선택할 수 있습니다.
출발지 선택이 바뀌면 검색 입력란, 확정한 장소, 지도 마커도 함께 반영합니다.
검색어를 입력하거나 후보를 미리 보는 것만으로 기존 출발지가 바뀌지는 않습니다.

현재 위치를 선택하면 기기가 보고한 위치 오차 범위를 표시합니다.
주소 조회에 실패해도 확보한 좌표는 유지하고 ‘주소 확인 필요’를 표시합니다.
위치 권한 거부나 조회 실패 시에는 기존에 확정한 출발지를 유지합니다.

여행 상태는 sessionStorage에 저장합니다.
등록하지 않은 대화 입력문과 검색 중인 검색어는 저장하지 않습니다.
저장본이 없거나 형식·버전이 맞지 않으면 기본 상태로 시작합니다.

## 2. 개발 실행·지도 설정

개발 확인 환경은 Windows, Node.js 24, npm 11입니다.
프로젝트 루트에서 실행합니다.

```cmd
npm --prefix frontend ci
npm --prefix frontend run dev
```

| 항목 | 설정 |
|---|---|
| 로컬 환경변수 파일 | frontend/.env.local |
| 환경변수 이름 | VITE_KAKAO_MAP_KEY |
| 키 종류 | 카카오 지도 SDK용 JavaScript 키 |
| 등록한 SDK 도메인 | http://localhost:5173 |
| 개발 서버 | 5173 포트를 사용하며, 해당 포트가 사용 중이면 실행을 중단합니다. |

.env.local에 실제 JavaScript 키를 설정합니다.
환경변수를 변경하면 개발 서버를 재시작합니다.

.env.local은 Git에서 제외하고, .env.example에는 변수 이름만 공유합니다.
지도용 JavaScript 키는 브라우저에서 사용하며, 교통·LLM API 키는 백엔드에서 관리합니다.

## 3. 코드·패키지 관리

| 파일·폴더 | 역할 |
|---|---|
| frontend/src/App.jsx | 화면 전환, 여행 조건, 확정한 출발지, 추가 요청 상태를 관리합니다. |
| frontend/src/OriginPicker.jsx | 센터·현재 위치·검색 결과 선택과 검색 입력값을 관리합니다. |
| frontend/src/OriginMap.jsx | 장소 검색, 후보 미리보기, 출발지 확정, 지도·마커 복원을 처리합니다. |
| frontend/src/TripSummary.jsx | 조건 요약과 출발지 변경 버튼, 사용자 요청 대화창을 표시합니다. |
| frontend/src/services/ | 지도 SDK 로딩, 기기 위치 조회, 센터 주소·현재 위치 주소 조회, 여행 상태 저장·복원을 처리합니다. |

좌표 필드에서 latitude는 위도, longitude는 경도입니다.
카카오 검색 응답의 y를 위도, x를 경도로 변환합니다.

프론트 의존성은 package.json과 package-lock.json으로 공유합니다.
node_modules, dist, .env.local은 Git에서 제외합니다.

ESLint 하위 패키지 취약점 대응으로
overrides.eslint.minimatch를 11.0.3으로 지정했습니다.
의존성 갱신 시 해당 설정의 필요성을 재검토합니다.

## 4. 검증

프로젝트 루트에서 실행합니다.

```cmd
npm --prefix frontend run lint && npm --prefix frontend run build
```

2026-11-09 기준 lint와 빌드가 통과했습니다.
다음 항목은 개발자가 브라우저에서 수동으로 확인했습니다.

| 확인 항목 | 결과 |
|---|---|
| 기본 출발지 | 센터 이름·주소와 지도 마커가 표시됩니다. |
| 출발지 변경 | 장소 검색·확정, 현재 위치 사용, 센터 재선택에 따라 출발지와 마커가 바뀝니다. |
| 검색 입력값 | 출발지를 확정하면 입력란도 해당 장소 이름으로 바뀝니다. |
| 현재 위치 | 조회된 위치로 마커가 이동하고 기기가 보고한 위치 오차 범위가 표시됩니다. |
| 화면 이동·복원 | 요약에서 출발지 변경 후 첫 화면으로 돌아가며, 같은 탭의 새로고침과 조건 화면 재진입 시 기존 상태가 유지됩니다. |

위치 권한 거부, 위치 조회 불가, 시간 초과에 대한 실제 기기 수동 검증은 아직 확인하지 않았습니다.

## 5. 남은 연동

| 항목 | 남은 작업 |
|---|---|
| Agent·일정 | 프론트 조건과 백엔드 API 형식을 맞추고, 요청 전송·대기·오류 처리와 생성된 일정 표시를 연결합니다. |
| 여행 지도 | 방문 장소와 자동차·대중교통·도보 이동 경로를 지도에 표시합니다. |

현재 지도는 출발지 선택용입니다.
지도 좌표나 경로의 존재만으로 이동약자의 통행 가능 여부를 판단하지 않습니다.

추가 요청 기능은 [사용자 요청 대화창](travel-chat.md)을 참고합니다.
