# 여행 조건·출발지 선택·일정 생성 UI

> 현재 메인 화면은 POST /chat을 사용하는 대화형 UI입니다.
> 최신 실행 방법과 검증 상태는 [대화형 여행 플래너](chat-planner.md)를 참고합니다.
> 아래 내용은 단계형 UI와 기존 POST /plan 연동을 기준으로 작성되었습니다.

최종 검증일: 2026-11-10

## 1. 구현 범위

| 기능 | 구현 내용 |
|---|---|
| 출발지 선택 | 센터 출발, 장소 검색, 현재 위치 중 하나로 출발지를 정합니다. |
| 여행 조건 입력 | 여행 종류, 이동수단, 날짜·시간, 필수 이용 조건, 휴식·귀환 여부를 선택합니다. |
| 추가 요청 | 요청 등록·삭제와 합산 1,000자 제한을 제공합니다. |
| 일정 생성·표시 | 조건을 API에 전달하고 생성 중 상태, 오류, 방문·이동 시간표와 접근성 메모를 표시합니다. |
| 새로고침 복원 | 현재 화면, 출발지, 여행 조건, 등록한 요청과 생성 완료된 일정을 같은 탭에서 복원합니다. |

**출발지 선택**

| 방식 | 동작 |
|---|---|
| 센터에서 출발 | 설정한 센터 주소를 검색하여 이름·주소·좌표를 설정합니다. |
| 장소 검색 | 제주 지역 후보를 최대 5개 표시하고, 사용자가 지도에서 확인한 뒤 확정합니다. |
| 현재 위치 사용 | 버튼을 눌렀을 때 기기 위치를 한 번 조회하고 오차 범위를 표시합니다. |

센터 주소 설정값은 `제주특별자치도 제주시 첨단로 241`입니다.
저장된 출발지가 있으면 해당 장소를 복원합니다.
검색어 입력이나 후보 미리보기만으로 확정한 출발지가 바뀌지는 않습니다.

출발지를 확정하면 검색 입력란과 지도 마커도 해당 장소로 맞춥니다.
현재 위치의 주소 조회에 실패해도 확보한 좌표는 유지합니다.
위치 조회 자체가 실패하면 기존에 확정한 출발지를 유지합니다.

**일정 생성과 수정**

요약 화면의 ‘일정 만들기’를 누르면 등록된 추가 요청과 현재 여행 조건을 전달합니다.
생성 중에는 중복 요청과 조건 변경을 막기 위해 생성·수정·삭제 버튼과 요청 입력을 잠급니다.
프론트의 응답 대기 제한은 3분입니다.

조건 수정 화면이나 출발지 선택 화면으로 이동하거나,
추가 요청을 등록·삭제하면 이전 일정 결과를 초기화합니다.
변경한 조건으로 다시 생성할 때는 사용자가 버튼을 누릅니다.

휴식은 방문 체류시간에 포함하고 해당 항목의 메모에 표시합니다.
‘여행지 자료 등록’은 자료 목록에 포함된 장소라는 뜻이며,
실제 접근성 충족을 보장하는 표시는 아닙니다.

**저장과 복원**

여행 상태는 sessionStorage에 저장합니다.
완료된 일정은 새로고침 시 복원하며 일정 생성 API를 자동으로 다시 호출하지 않습니다.
저장된 일정 형식이 잘못되었으면 일정 결과만 비우고 여행 조건은 유지합니다.

검색 중인 검색어와 등록하지 않은 요청 초안은 저장하지 않습니다.
진행 중인 일정 생성 요청의 재연결·재개 기능은 구현하지 않았습니다.

## 2. 개발 실행과 지도 설정

개발 확인 환경은 Windows, Node.js 24, npm 11입니다.
프로젝트 루트에서 실행합니다.

```cmd
npm --prefix frontend ci
npm --prefix frontend run dev
```

일정 생성에는 별도로 실행한 백엔드가 필요합니다.
백엔드 실행 방법과 입력·출력은 [API 명세](api.md)를 참고합니다.

| 항목 | 설정 |
|---|---|
| 지도 환경변수 파일 | frontend/.env.local |
| 환경변수 이름 | VITE_KAKAO_MAP_KEY |
| 키 종류 | 카카오 지도 SDK용 JavaScript 키 |
| SDK 도메인 | http://localhost:5173 |
| API 프록시 | /api 요청을 http://127.0.0.1:8000 으로 전달하며 /api 접두사를 제거합니다. |

개발 서버는 5173 포트를 사용하며, 해당 포트가 사용 중이면 실행을 중단합니다.
환경변수를 변경하면 프론트 개발 서버를 재시작합니다.

.env.local은 Git에서 제외하고 .env.example에는 변수 이름만 공유합니다.
지도 JavaScript 키는 브라우저에서 사용하고, 교통·LLM API 키는 백엔드에서 관리합니다.
지도와 실제 일정 생성에는 외부 서비스 연결이 필요합니다.

## 3. 코드와 패키지 관리

| 파일·폴더 | 역할 |
|---|---|
| src/App.jsx, src/services/travelSession.js | 화면·입력·요청·일정 상태 관리와 저장·복원을 처리합니다. |
| src/TripSummary.jsx, src/TravelPlan.jsx | 요약, 생성 버튼, 상태·오류 안내와 일정표를 표시합니다. |
| src/TravelChat.jsx | 추가 요청 입력·등록·삭제와 합산 글자 수를 관리합니다. |
| src/OriginPicker.jsx, src/OriginMap.jsx | 출발지 선택과 검색·지도 표시를 처리합니다. 관련 지도·위치 서비스는 src/services/에 있습니다. |
| src/services/planRequest.js, src/services/planApi.js | 화면 값을 API 요청으로 변환하고 요청·오류·응답 형식 검사를 처리합니다. |

위도는 latitude, 경도는 longitude입니다.
카카오 응답의 y를 위도, x를 경도로 변환합니다.

프론트 의존성은 package.json과 package-lock.json으로 공유합니다.
node_modules, dist, .env.local은 Git에서 제외합니다.

ESLint 하위 의존성 대응으로 overrides.eslint.minimatch를 11.0.3으로 지정했습니다.
의존성 갱신 시 해당 설정의 필요성을 재검토합니다.

프로젝트 루트에서 실행합니다.

```cmd
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
npm --prefix frontend run lint && npm --prefix frontend run build
```

2026-11-10 기준 전체 Python 테스트 73개와 프론트 lint·빌드가 통과했습니다.

아래 브라우저 확인 항목은 시간 검증 추가 전의 연동 검증 기록입니다.

| 항목 | 확인 결과 |
|---|---|
| 서버 연결 | 백엔드 직접 호출과 프록시 경유 /health 모두 200 OK |
| 실제 일정 생성 | 센터 출발, 자연·산책, 자동차, 장애인 화장실, 20분 휴식, 귀환 조건으로 일정 표시 |
| 시간표 | 2026-11-11의 13:00~17:00 조건에서 센터→절물휴양림→센터 일정이 표시되었으며 귀환 시각은 15:34 |
| 생성 중 상태 | 생성 중 안내와 생성·수정·삭제 버튼 및 요청 입력 잠금 확인 |
| 새로고침 | 같은 탭에서 기존 일정표가 유지됨을 확인 |

도보·대중교통의 실제 Agent 일정 생성은 이번 검증에 포함하지 않았습니다.

## 5. 남은 작업

| 항목 | 내용 |
|---|---|
| 일정 지도 | 방문 장소와 자동차·대중교통·도보 경로를 지도에 표시합니다. 현재 지도는 출발지 선택용입니다. |
| 대화로 부분 수정 | 현재는 등록한 요청을 모아 일정을 새로 생성합니다. 기존 일정의 대화 기반 부분 수정은 미구현입니다. |
| 결과 재검증 | 시간표 형식·범위·겹침·소요시간 검사는 구현했습니다. 도구 조회값 대조, 귀환·휴식 반영, 운영시간과 필수 접근 조건 근거 검증은 남아 있습니다. |
| 실행·배포 | 현재는 개발 서버 실행을 확인했으며, 배포 환경의 API 연결과 실행 절차는 별도로 구성해야 합니다. |

추가 요청의 저장·전달 방식은 [사용자 요청 대화창](travel-chat.md)을 참고합니다.
