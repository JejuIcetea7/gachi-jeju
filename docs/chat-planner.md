# 대화형 여행 플래너

검증일: 2026-11-10

이번 공유 범위는 대화형 UI와 장소 위치 지도입니다.
실제 자동차·도보·대중교통 이동 경로선은 연결 중입니다.

────────────────────────────────────────

## 1. 현재 기능

| 항목 | 동작 |
|---|---|
| 화면 구성 | 왼쪽 여행 옵션, 가운데 대화창, 오른쪽 지도·일정표를 표시합니다. |
| 선택 옵션 | 출발지, 날짜·기간, 이동수단, 보조기구, 여행 종류, 접근 조건, 귀환 여부를 선택합니다. 옵션을 비워 두고 대화로 시작할 수도 있습니다. |
| 대화 | 요청과 선택 옵션을 함께 전달합니다. 부족한 정보를 질문하거나 일정을 생성·수정합니다. |
| 장소 지도 | 출발지와 확인된 방문 좌표를 표시합니다. 장소 버튼, 전체 위치 보기, 일정표 독립 스크롤을 제공합니다. |
| 상태 복원 | 같은 탭에서 새로고침하면 옵션·대화·일정을 복원합니다. ‘새 여행 시작’으로 초기화합니다. |

여행 기간은 당일·1박 2일·2박 3일을 지원합니다.
시작·종료 시각과 중간 휴식은 선택 옵션에서 제외했으며, 대화에 요청할 수 있습니다.

기본 출발지는 제주빅데이터센터입니다.
센터 주소 설정값은 `제주특별자치도 제주시 첨단로 241`입니다.
장소 검색 또는 현재 위치 사용으로 변경할 수 있습니다.

‘여행지 자료 등록’은 DB에 등록된 장소라는 뜻입니다.
이용 가능한 동선과 편의시설은 일정 항목의 접근성 안내를 확인해야 합니다.

## 2. 개발 실행

Python 3.12 가상환경 `.venv`와 Node.js·npm을 사용하는 환경입니다.
프로젝트 루트에서 두 터미널을 사용합니다.

**환경변수**

| 파일 | 변수 |
|---|---|
| 루트 `.env` | `KAKAO_REST_API_KEY`, `OPENAI_API_KEY` |
| `frontend/.env.local` | `VITE_KAKAO_MAP_KEY` — 지도 SDK용 JavaScript 키 |

실제 키는 Git에 포함하지 않습니다.
지도 앱의 허용 도메인에 `http://localhost:5173`을 등록합니다.

**백엔드 터미널**

```cmd
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

**프론트 터미널**

```cmd
npm --prefix frontend ci
npm --prefix frontend run dev
```

[프론트 화면](http://localhost:5173)에서 확인합니다.
[자동 API 명세](http://127.0.0.1:8000/docs)에서 요청·응답 스키마를 확인할 수 있습니다.

Vite는 `/api` 요청을 백엔드로 전달하면서 `/api` 접두사를 제거합니다.
환경변수를 변경하면 해당 개발 서버를 재시작합니다.

## 3. 대화 API

브라우저는 `POST /api/chat`, 백엔드는 `POST /chat`을 사용합니다.

**최소 요청 예시**

```json
{
  "message": "자동차를 이용해 휠체어로도 편하게 돌아다닐 수 있는 관광지에 가고 싶어요."
}
```

추가로 `options`, `history`, `current_plan`을 전달할 수 있습니다.
메시지는 한 번에 최대 1,000자이며, 이전 대화는 전송 완료된 메시지 중 최근 20개까지 전달합니다.

| 응답 필드 | 내용 |
|---|---|
| `reply` | Agent 답변·추가 질문·변경 요약 |
| `options` | 대화까지 반영한 현재 선택 조건 |
| `plan` | 생성·수정한 전체 일정. 질문이나 일반 답변이면 null |
| `warnings` | 확인이 필요한 항목 |
| `meta` | 호출 횟수와 처리시간 등 실행 정보 |

질문만 반환되면 기존 일정은 유지합니다.
옵션 변경은 다음 메시지에 함께 반영하며, 기존 결과에는 이전 일정임을 표시합니다.

응답 대기 중에는 입력과 옵션 변경을 잠급니다.
실패한 요청은 사용자가 다시 보낼 수 있으며, 새로고침 후 자동 재전송하지 않습니다.

## 4. 검증 기록

```cmd
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_*.py" -v
npm --prefix frontend run lint && npm --prefix frontend run build
```

전체 Python 테스트 117개와 프론트 lint·빌드가 통과했습니다.

브라우저에서는 자동차·휠체어·당일 여행 시나리오로 다음을 확인했습니다.

| 항목 | 확인 내용 |
|---|---|
| 대화와 일정 | 자연어 옵션 반영, 일정 생성, 특정 장소 제외 요청에 따른 수정 |
| 새로고침 | 옵션·대화·생성된 일정 유지 |
| 지도 | 방문 장소 반영, 장소 버튼, 전체 위치 보기, 지도와 일정표의 동시 확인 |
