# 사용자 요청 대화창

검증일: 2026-11-09

## 1. 구현 범위

여행 조건 요약과 지도 사이에서 사용자의 추가 요청을 받습니다.
현재는 요청 입력과 브라우저 내 보관까지 구현되어 있습니다.

| 기능 | 동작 |
|---|---|
| 요청 입력 | 최대 1,000자를 입력하며, 공백만 있으면 추가할 수 없습니다. |
| 요청 추가 | 앞뒤 공백을 제거해 목록에 추가하고 입력창을 비웁니다. |
| 요청 표시 | 작성 순서와 줄바꿈을 유지하고 긴 목록은 스크롤로 확인합니다. |
| 조건 연결 | 각 요청에 작성 당시의 여행 조건을 함께 저장합니다. |
| 내역 유지 | 여행 조건을 수정하고 돌아와도 추가한 요청 내역은 유지됩니다. |

추가한 요청 내역은 여행 조건과 함께 sessionStorage에 저장하며,
같은 탭에서 새로고침해도 복원합니다.
입력창의 문장은 ‘요청 추가’를 눌러 목록에 등록한 뒤 저장됩니다.
추천 답변은 Agent 연동 이후 제공할 예정입니다.

## 2. 코드 구성

| 파일 | 역할 |
|---|---|
| frontend/src/App.jsx | 요청 내역과 작성 당시의 여행 조건을 저장합니다. |
| frontend/src/TripSummary.jsx | 요약 화면에 대화창을 연결합니다. |
| frontend/src/TravelChat.jsx | 입력 검사, 요청 추가, 요청 목록 표시를 처리합니다. |
| frontend/src/App.css | 대화창·입력창·요청 목록과 좁은 화면의 스타일을 정의합니다. |

## 3. 요청 저장 형식

각 요청은 다음 필드로 관리합니다.

| 필드 | 내용 |
|---|---|
| id | 브라우저에서 생성한 UUID입니다. |
| role | 현재는 사용자 요청을 뜻하는 user입니다. |
| content | 앞뒤 공백을 제거한 요청 문자열입니다. |
| conditions | 요청을 작성한 당시의 여행 조건 요약입니다. |

conditions에는 출발지, 선택한 장소와 좌표, 여행 종류,
이동수단, 날짜·시간, 필수 이용 조건, 휴식·귀환 조건이 포함됩니다.
장소를 확정하지 않았다면 originPlace는 null입니다.

백엔드 연동 시 API 요청·응답 형식은 팀원과 확정합니다.

## 4. 검증

프로젝트 루트에서 실행합니다.

```cmd
npm --prefix frontend run lint
npm --prefix frontend run build
```

2026-11-09 기준 lint와 빌드가 통과했습니다.
개발자가 브라우저에서 다음 동작을 확인했습니다.

- 요청 추가 후 목록 표시와 입력창 초기화.
- 공백만 입력한 요청 차단과 최대 1,000자 제한.
- 줄바꿈과 요청 작성 순서 유지.
- 긴 목록 스크롤과 좁은 화면에서의 문장 표시.
- 여행 조건 수정과 같은 탭의 새로고침 후 기존 요청 내역 유지.

요청마다 conditions를 저장하는 구조는 코드에서 확인했습니다.

## 5. 남은 연동

| 항목 | 남은 작업 |
|---|---|
| Agent API | 사용자 요청·여행 조건을 백엔드에 전달합니다. |
| 응답 처리 | Agent 답변·추가 질문과 응답 대기·오류·재시도를 처리합니다. |
| 결과 표시 | 추천 여행지·일정표·지도 경로를 응답 데이터와 연결합니다. |
