# 사용자 추가 요청과 일정 생성

> 현재 메인 화면은 POST /chat을 사용하는 대화형 UI입니다.
> 최신 실행 방법과 검증 상태는 [대화형 여행 플래너](chat-planner.md)를 참고합니다.
> 아래 내용은 단계형 UI와 기존 POST /plan 연동을 기준으로 작성되었습니다.

최종 검증일: 2026-11-10

## 1. 이용 흐름

요약 화면에서 추가 요청을 등록한 뒤 ‘일정 만들기’를 누르면,
현재 여행 조건과 등록된 요청을 함께 Agent에 전달합니다.
추천 결과는 별도의 일정표로 표시합니다.

| 기능 | 동작 |
|---|---|
| 요청 등록 | 앞뒤 공백을 제거해 목록에 추가합니다. 공백만 있는 요청은 등록할 수 없습니다. |
| 글자 수 제한 | 등록된 요청과 현재 입력을 합산해 표시합니다. 전체 요청은 최대 1,000자이며, 요청 사이 줄바꿈도 포함합니다. |
| 요청 삭제 | 등록한 요청을 삭제하고 합산 글자 수를 다시 계산합니다. |
| 생성 중 잠금 | 일정 생성 중에는 요청 입력·등록·삭제를 잠급니다. |
| 저장·복원 | 등록된 요청과 완료된 일정은 같은 탭에서 새로고침해도 복원합니다. |

입력창의 문장은 ‘요청 추가’를 눌러 등록한 뒤 저장되고 일정 생성에 사용됩니다.
등록하지 않은 초안은 저장·전송 대상에 포함되지 않습니다.

요청을 등록하거나 삭제하면 이전 일정 결과를 초기화합니다.
새 일정을 만들려면 사용자가 ‘일정 만들기’를 누릅니다.
요청 등록·삭제만으로 일정 생성 API를 호출하지 않습니다.

조건 수정 화면으로 이동하면 이전 일정은 초기화되지만 요청 내역은 유지됩니다.
변경한 조건에 맞지 않는 요청은 삭제한 뒤 다시 등록할 수 있습니다.

## 2. 저장과 전달 형식

각 요청은 다음 필드로 관리합니다.

| 필드 | 내용 |
|---|---|
| id | 브라우저에서 생성한 UUID |
| role | 현재는 사용자 요청을 뜻하는 user |
| content | 앞뒤 공백을 제거한 요청 문자열 |
| conditions | 요청을 등록한 당시의 여행 조건 요약 |

conditions에는 출발지·좌표·여행 종류·이동수단·날짜·시간·시설·휴식·귀환 조건이 포함됩니다.

일정 생성 시에는 현재 요약 화면의 조건을 사용합니다.
각 요청에 저장된 과거 conditions를 현재 조건 대신 사용하지 않습니다.

role이 user인 요청의 content만 정리하여 줄바꿈으로 합치고,
API의 message 필드로 전달합니다.
합산 결과가 1,000자를 넘으면 API 호출 전에 오류를 표시합니다.

요청·응답의 전체 규격은 [API 명세](api.md)를 참고합니다.

## 3. 코드 구성

| 파일 | 역할 |
|---|---|
| frontend/src/App.jsx | 요청 등록·삭제, 일정 생성, 결과·오류 상태와 중복 실행 방지를 처리합니다. |
| frontend/src/TravelChat.jsx | 입력, 합산 글자 수, 요청 목록·삭제 버튼과 생성 중 잠금을 표시합니다. |
| frontend/src/TripSummary.jsx, frontend/src/TravelPlan.jsx | 생성 버튼, 대기·오류 안내와 추천 일정표를 표시합니다. |
| frontend/src/services/planRequest.js, frontend/src/services/planApi.js | 요청 변환, 합산 길이 검사, API 호출·오류·응답 형식 검사를 처리합니다. |
| frontend/src/services/travelSession.js | 여행 조건·등록 요청·완료된 일정의 저장과 복원을 처리합니다. |

부모가 요청 등록을 거절하면 입력 초안을 유지합니다.
요청 등록·삭제 후에는 입력창으로 초점을 이동하도록 구성했습니다.

## 4. 검증 상태

프로젝트 루트에서 실행합니다.

```cmd
.venv\Scripts\python.exe -B -m unittest discover -s tests -p "test_plan*.py" -v
npm --prefix frontend run lint && npm --prefix frontend run build
```

2026-11-10 기준 전체 Python 테스트 73개가 통과했습니다.
이 중 일정 API·입력 전달·시간 검증 관련 테스트는 27개입니다.
프론트 lint와 빌드도 통과했습니다.

생성 일정의 시간 오류가 HTTP 502로 반환되는 동작은 mock 기반 API 테스트로 확인했습니다.

API 테스트에는 조건 전달, 잘못된 입력의 Agent 호출 차단,
추가 요청 1,000자 허용·1,001자 차단 검사가 포함됩니다.

시간 검증 추가 전 브라우저에서는 실제 자동차 일정 생성·표시,
생성 중 입력 잠금과 새로고침 후 결과 유지를 확인했습니다.

새 합산 글자 수의 모든 경계 사례, 요청 삭제와 오류 화면 전체를
실제 브라우저에서 수동 검증한 것은 아닙니다.

## 5. 현재 범위와 남은 기능

현재는 등록된 요청을 모아 일정을 새로 생성하는 방식입니다.
대화 ID를 유지하며 기존 일정의 일부를 수정하는 기능은 구현하지 않았습니다.

등록한 요청의 직접 편집 기능은 없으며, 삭제 후 다시 등록하는 방식으로 수정합니다.
방문 장소와 이동 경로의 결과 지도 연동도 별도 작업입니다.
