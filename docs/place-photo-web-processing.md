### 재압축 중 구체화한 사항

- 기존 무손실 WebP를 입력으로 재압축했으며 원본에서 다시 축소하지 않았다.

- 대상의 `web_lossless_verified`는 `False`로 변경했다. 손실 압축이라는 뜻이며 파일 손상을 뜻하지 않는다. 유지한 사진은 `True`다.
- 모든 사진의 파일명·장소 연결·설명은 유지했다. 검증 결과는 `outputs/photo_web/verification.json`에 갱신하고 이전 무손실 결과는 `recompression-85/previous_verification.json`에 보관했다.
- 기존의 큰 WebP는 중복 보관하지 않고 교체했다. 원본 사진에서 재생성할 수 있으며 이전 목록·검증 기록은 보관했다.
- 관련 자동 테스트 11개가 통과했다. 재실행으로 손실 압축을 반복하지 않도록 기존 재압축 작업 디렉터리가 있으면 처리를 시작하지 않는다.

## 1차 무손실 가공 기준(이력)

1. **크기:** 긴 변이 1,600px를 넘으면 긴 변이 최대 1,600px가 되도록 축소한다. 나머지는 크기를 유지한다. 가로·세로 비율을 유지하고 자르기·여백 추가·작은 사진 확대는 하지 않는다. 정수 픽셀 반올림 차이는 허용한다.
2. **압축:** 모든 사본을 무손실 WebP로 저장한다. 축소 후의 픽셀을 인코딩할 때 추가 손실이 없다는 뜻이며, 해상도 축소 자체는 원래의 세부 정보를 줄인다.
3. **설정:** 현재 설치된 Pillow 12.0.0을 사용한다. `lossless=True`, `quality=100`, `method=4`, `exact=True`로 저장한다. 무손실 모드의 `quality`는 화질 손실률이 아니라 압축에 들이는 노력 수준이며, `method=4`는 처리 시간과 압축 효율의 균형을 위한 선택이다.
4. **사진 방향:** EXIF의 회전·반전 정보를 픽셀에 적용한 후 축소한다. 웹용 파일에 방향 메타데이터가 없어도 바르게 보이도록 한다.
5. **색상:** RGB 또는 투명도를 보존하는 RGBA로 저장하고, 원본에 ICC 색상 프로필이 있으면 함께 보존한다. EXIF·GPS·촬영 장비 정보는 웹용 파일에 복사하지 않으며 원본에는 그대로 남는다.
6. **복수 이미지 파일:** MPO 등 여러 프레임이 있는 원본은 첫 번째 프레임을 웹용 대표 이미지로 사용한다. 원본의 나머지 프레임은 원본 파일에 보존한다. 입력 프레임 수와 선택한 프레임 번호를 웹용 목록에 기록한다.
7. **용량 증가:** 일부 무손실 WebP가 기존 JPEG보다 커져도 손실 압축으로 바꾸지 않는다. 전부 WebP·무손실이라는 합의 기준을 우선하고 증가한 파일 수와 용량을 별도 보고한다.

실제 입력은 RGB 2,538개·RGBA 1,295개·CMYK 1개다. CMYK 1개는 원본 ICC 프로필로
sRGB로 변환한 뒤 웹용 RGB로 저장하고 변환 사실을 기록한다. 이 파일의 프로필은
원본 CMYK 프로필을 그대로 붙이지 않고 변환 결과에 맞는 sRGB 프로필을 사용한다.
전체 ICC 프로필 포함 파일은 88개다. 방향 보정 대상은 375개(90도 회전 374개·180도 회전 1개),
복수 프레임 원본은 138개다.

설정 근거: [Pillow WebP 저장 옵션](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#webp),
[EXIF 방향 적용](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose).

## 실행 순서

1. 입력 목록과 실제 파일 수·내용 검사값, 지원 형식, 방향·프레임·색상 정보를 확인한다.
2. 작은 사진·큰 가로/세로 사진·PNG/BMP·복수 프레임·투명도·회전 사례로 가공 및 검증 코드를 시험한다.

5. 원본 내용이 바뀌지 않았는지 다시 확인하고 웹용 CSV와 전체 용량·크기 변화 보고서를 작성한다.

### 작업 중 구체화한 결정

1. **별도 CSV:** 원본 목록을 보존하기 위해 웹용 목록을 `place_photos_web.csv`로 분리했다. 기존 출처·설명을 그대로 복사하고 웹용 속성만 추가했다.
2. **압축 노력 수준:** `quality=100`, `method=4`를 사용했다. 화질 손실을 허용한 설정이 아니며, 전체 파일에 `lossless=True`를 적용했다.
3. **투명 영역 보존:** 투명한 픽셀의 RGB 값도 보존하도록 `exact=True`를 사용했다. RGBA 이미지의 모든 채널을 픽셀 비교에 포함했다.
4. **방향과 메타데이터:** 375개의 회전 정보를 픽셀에 반영하고, 웹용 파일에는 EXIF·GPS·촬영 장비 정보를 복사하지 않았다. 색상 표시에 필요한 ICC 프로필은 유지했다.
5. **CMYK 1개:** `P120_0011`은 원본 ICC 프로필에 따라 sRGB로 변환했다. 웹용 목록에 `CMYK_ICC_to_sRGB`로 기록했다. 이 경우 무손실 검증 기준은 색상 변환·축소 후의 RGB 픽셀이다.
6. **MPO 138개:** 원본에 담긴 2개 프레임 중 첫 번째를 웹용 대표 이미지로 사용했다. 원본 2개 프레임은 그대로 보존했다.
7. **처리·재개:** 작업은 최대 4개 병렬로 처리했다. 중단 후에는 기존 WebP를 기준 픽셀과 비교한 뒤 일치할 때만 재사용한다. 최종 CSV는 전체 검증을 통과한 후 작성하며 기존 완성 목록은 덮어쓰지 않는다.
8. **용량 증가 유지:** 무손실·WebP 통일 기준에 따라 커진 파일 1,983개도 결과에 포함했다. 임의로 손실 압축을 추가하지 않았다.
9. **Git 제외:** 웹용 사진과 진행·검증 기록을 Git에서 제외했다. 스크립트·테스트·문서·웹용 CSV는 관리 대상으로 남겼다.
