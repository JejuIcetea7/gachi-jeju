# build_places 임의 결정 목록

사용자와 상의하지 않고 정한 내용이다. 확인되면 상태를 `확인`으로 바꾼다.

## 이름 · 구조

| 번호 | 결정 | 이유 | 상태 |
| --- | --- | --- | --- |
| 1 | 브랜치 이름 `data/integrate-places` | 원격 `data/data-go-kr-barrier-free`와 같은 형식 | 미확인 |
| 2 | 파일 이름: `scripts/build_places.py`, `docs/plans/build_places.md`, `place_id_map.csv`, `gachi_jeju.db`, `outputs/build_places/` | 하는 일을 그대로 쓴 이름 | 미확인 |
| 3 | 스크립트를 나누는 단위: 원본 형식 6종마다 변환 함수 1개씩 (`convert_hub_number_spots`, `convert_place_name_50_spots`, `convert_place_name_20_spots`, `convert_course_spots`, `convert_nearby_info`, `convert_nearby_etc`), 나머지는 작업 단계마다 1개 (예: `merge_split_spot_rows`, `find_duplicate_candidates`) | 형식이 늘면 함수 하나만 추가하면 됨 | 미확인 |
| 4 | 읽기 실패·예상과 다른 컬럼은 실패 로그에 남기고 다음 파일로 넘어감 | 한 파일 때문에 전체가 멈추지 않게 | 미확인 |
| 5 | 실행은 옵션 없이 `python3 scripts/build_places.py` 한 번 | 단계 전체를 한 번에 재현 | 미확인 |
| 6 | SQLite는 매번 지우고 새로 만듦. `latitude`·`longitude`는 REAL, `order`·`distance_m`·`visit_minutes`는 INTEGER, 나머지 TEXT. 빈칸은 NULL. `place_id` 인덱스 추가 | CSV에서 다시 만들 수 있게 | 미확인 |
