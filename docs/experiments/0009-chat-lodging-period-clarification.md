# 0009. 당일 일정의 숙박 기간 확인과 귀환 전용 날짜

검증일: 2026-11-18

당일 일정에서 숙소를 요청할 때 여행 기간을 확인하고,
동의 후 숙소와 마지막 날 귀환을 반영하는 흐름을 검증했습니다.
자동 테스트와 사용자가 제공한 브라우저 화면을 기준으로 기록했습니다.

────────────────────────────────────────

## 1. 변경 내용

작업 브랜치는 `fix/chat-lodging-period-clarification`입니다.

| 상황 | 처리 |
|---|---|
| 당일 일정에서 숙박 추가·변경을 요청함 | 모델·교통 API 호출 전에 1박 2일로 늘릴지 질문합니다. 기간과 기존 일정은 유지합니다. |
| 바로 앞의 기간 질문에 짧게 동의함 | 1박 2일 조건을 준비하고 앞서 지정한 숙소 요청을 Agent에 함께 전달합니다. |
| 바로 앞의 기간 질문에 `아니요`라고 답함 | 당일 조건을 유지하는 답변을 반환합니다. |
| 사용자가 기간이나 날짜를 직접 지정함 | 기존 Agent 흐름에서 명시한 조건을 처리합니다. |
| 마지막 날에 관광지 방문 요청이 없음 | 숙소와 출발지가 확인되고 귀환을 요청했다면 귀환 이동만 구성할 수 있습니다. |
| 모든 숙박일의 숙소가 선택됨 | 숙소가 미정이거나 제공되지 않았다는 명시적인 설명을 검사합니다. |

짧은 동의는 바로 앞의 정해진 기간 확인 질문에 대한 답변일 때만 처리합니다.
무관한 질문에 대한 `네`를 기간 연장으로 해석하지 않습니다.

기간 확인과 거절 응답의 `plan`은 `null`이며,
화면은 기존 지도와 일정을 유지하는 기존 응답 처리를 사용합니다.

새 숙소에는 이번 실행의 위치 조회 근거가 계속 필요합니다.
기간 동의를 숙소 좌표의 확인 근거로 사용하지 않습니다.

────────────────────────────────────────

## 2. 발견한 오류와 보완

| 오류 | 보완 |
|---|---|
| 당일 조건에 숙박일을 넣어 응답 형식 검증에 실패함 | 숙박 기간 확인을 모델 호출 전에 처리하고 동의한 기간을 입력 조건에 반영합니다. |
| 2일차에 관광지가 없다는 이유로 귀환까지 생략함 | 전날 일정이 있고 선택한 전날 숙소·원래 출발지가 확인되며 귀환을 요청한 경우, 마지막 날 귀환 이동의 누락을 검사합니다. |
| 선택한 숙소가 있는데 숙소 미제공 안내가 남음 | 모든 숙박일의 선택이 있는 경우 `reply`와 `assumptions`의 명시적인 숙소 미정·미제공 설명을 검사합니다. |

누락된 귀환과 설명 모순은 기존 최대 1회 자동 재생성에 연결합니다.
재생성 후에도 실패하면 검증 오류를 반환합니다.

숙소가 미정이거나 귀환을 요청하지 않은 경우에는 귀환 경로를 만들도록 요구하지 않습니다.
전체 일정이 비어 있는 경우에도 숙소 여행을 임의로 만들어 넣지 않습니다.

귀환 누락과 숙소 안내 모순의 거부,

## 5. 확인 범위

최종 브라우저 캡처는 동의 후 연장 흐름의 근거입니다.
거절 응답과 기존 입력 보존은 자동 검사로 확인했으며,
거절 전후의 지도·일정 유지 화면은 별도로 확인하지 않았습니다.

이번 브라우저 검증의 원본 HTTP 응답, 모델 호출 수와 재생성 횟수는 수집하지 않았습니다.
반복 성공률과 여러 이동수단·긴 기간의 실제 생성 결과는 측정하지 않았습니다.

숙박 의도와 설명 검사는 정해진 표현 범위에 적용합니다.
일부 자연어 표현은 기존 Agent 흐름에서 처리하며,
모든 숙소 설명의 사실관계를 자동 판정하지는 않습니다.
