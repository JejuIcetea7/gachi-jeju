# Luna high 에이전트 종합 점검

현재 Agent는 저장된 일정의 변경과 여러 조건을 유지하는 작업을 수행했다. 복잡한 요청 8종을 각각 두 번 실행한 16건은 모두 자동 평가와 내용 확인을 통과했다. 귀환을 선택한 상태에서 새 일정을 만들고 점심 추가·점심 시각 변경·여행일 변경을 이어간 대화도 4단계 모두 통과했다.

일반 소개 질문의 정상 답변을 서버가 덮어쓰고, 자연어 귀환 요청을 기존 조건과 충돌한다고 처리하는 결함이 남았다. 일시적인 검색 오류의 재시도 제공과 인증 오류의 후속 안내도 불완전했다. 현재 성능을 모든 사용자 요청에 안정적인 상태로 평가하기는 어렵다.

## 평가 대상과 범위

- 모델은 GPT-6 Luna, 추론 수준은 high다. 평가 중 모델·프롬프트·실행 소스를 고정했다.
- 대상은 작업 브랜치 chore/agent-workflow-review의 미커밋 변경을 포함한 현재 구현이다.
- 실제 FastAPI /chat 처리 경로를 기존 평가 도구로 실행했다. 브라우저의 UI 조작과는 구분한다.
- 전체 35건 중 32건은 실제 모델과 실제 데이터·지도 도구를 사용했다. 3건은 실제 모델에 식당 조회 결과만 모의했다.
- 기본 질문 8건, 복잡한 요청 8종 각 2회인 16건, 실제 앞선 결과를 이어받는 대화 2개 각 4단계, 실패 모의 3건이다.
- 저장된 일정의 복잡한 수정은 이전 실험 입력을 사용해 당시 기준 날짜를 재현했다. 새 기본 질문·연속 대화의 기준일은 2026-11-19다.
- 휴식 요청 수정은 사용자 지시에 따라 평가 대상 변경에서 제외했다. 이번 점검 중 서비스 코드를 수정하지 않았다.

## 판정 방법

자동 통과는 HTTP 응답, 기대 응답 유형, 일정·조건·도구 조회 근거를 기존 평가기로 검사한 결과다.
이후 모델이 처음 작성한 답변과 실제 최종 응답을 읽고 질문에 답했는지 확인했다.
일정은 장소·방문일·체류시간·식사 시각·숙소·경로를 대조했다.

기본 질문은 정상 message 형식만으로도 자동 통과할 수 있다. 그래서 B01과 B04는 자동 통과지만 내용 확인에서 실패다.
빈 상태 대화의 2~4단계는 첫 실패의 영향을 받았으므로 독립된 세 가지 결함으로 세지 않는다.
귀환 선택 대화의 마지막 요청은 날짜 변경을 명시했다. 채점 시 기대 시작일을 2026-11-21로 지정해 원래 날짜를 유지해야 한다는 오판을 수정했다. 요청·응답 원본은 보존했다.

### 실제 연속 대화

기본 옵션을 비워 시작한 M01은 “센터로 돌아오는 당일 일정” 요청에 모델이 return_to_origin=true로 응답했지만 서버가 기존 false 조건 위반으로 거부했다. 이후에는 앞선 날짜·일수·이동수단이 대화에 있어도 일정을 복구하지 못했다.

별도 Q01은 처음부터 귀환 옵션만 true로 지정했다. 이 대화는 다음 실제 응답을 순서대로 이어받아 모두 성공했다.

1. 박물관 90분 관람과 센터 귀환 일정 생성.
2. 박물관 90분과 출발 시각을 유지하며 풍년밥상 12~13시 점심 추가.
3. 같은 박물관·식당을 유지하며 식사만 13~14시로 변경.
4. 출발·식사 시각과 장소·체류시간을 유지하며 여행일을 11월 21일로 변경.

### 검색 실패

- 빈 결과는 확인되지 않은 식당을 만들지 않고 검색 범위를 조정할지 물었다.
- 일시 서비스 오류는 기존 일정을 유지했지만 식당 검색 재시도 데이터가 없어 버튼이 제공되지 않았다.
- 인증 오류는 기존 일정을 유지했지만 사용자가 재요청하면 처리할 수 있다고 안내했다. 인증 설정 문제의 해결과 사용자 재시도는 구분해야 한다.
- 이 세 건의 외부 조회 실패는 모의했다. 실제 모델의 처리·서버 반환은 실행했으며 실제 외부 서비스 장애를 관측한 결과로 해석하지 않는다.

## 프롬프트 평가

현재 고정 지침은 8,875자다. 역할과 목표, 처리 절차, 예시, 입력 정보 순서로 구성돼 있고, 요청 판단→기존 조건 확인→도구 조회→일정 구성→실패 처리→응답의 단계가 드러난다.
기존 일정의 값 보존, 최신 조회가 필요한 사실, 미확인 접근성 안내와 식당 후보의 참조가 명시돼 있다.

단계별 구성과 명확한 행동 지시라는 방향은 공식 작성 지침에 부합한다. 길이만으로 품질을 판정할 수는 없고 실제 실행 결과로 판단해야 한다.

| 항목 | 판단과 근거 |
|---|---|
| 목적·정보 경계 | 적절. 기존 일정의 방문 조건과 도구로 다시 확인할 사실을 구분 |
| 기본 질문 대응 | 모델 답변은 대체로 질문에 맞았으나 서버 덮어쓰기 때문에 최종 사용자 응답이 손실 |
| 행동 분류 | 개선 여지. 정보 문의와 '일정을 만들지 마'가 함께 있으면 keep만 분류해 답변을 잃음 |
| 근거 인용 규칙 | 원문 검증은 가능하지만 유지·변경 구절의 겹침에 민감. 올바른 의미도 문장 분할에 따라 거부 가능 |
| 도구 사용 | 필요한 조회를 수행하지만 일부 실행에서 상세 조회 전에 경로를 요청. 서버가 details_required로 복구 |
| 재질문·문맥 유지 | 기본 부족 조건은 확인 가능. 첫 요청 실패 후 대화에 있던 조건의 복원은 불안정 |
| 실패 처리 | 지침은 구분하지만 실제 오류 응답이 전용 서버 처리에 들어가지 않으면 재시도·인증 안내가 일관되지 않음 |
| 길이·반복 | 처리 순서대로 정리돼 있다. 매 요청의 전체 지침·최근 대화·현재 일정·도구 결과가 반복 전달돼 호출 수에 따라 입력 토큰 증가 |

고정 지침을 계속 추가하는 것만으로 이번 두 기본 응답 결함을 해결하기 어렵다. 이미 모델이 정상 답변을 작성했고 서버에서 바뀌었기 때문이다.

## 안정성·검증 범위

- 서버는 재생성 최대 1회, 전체 요청 150초를 적용한다. 프런트 대기 제한은 180초다. 현재 평가의 요청은 모두 제한 시간 안에 종료했다.
- 이번 실행에서 무한 반복을 관찰하지 않았다. 업무별 모델·도구 호출 예산은 따로 명시돼 있지 않아 반복 호출 효율은 개선 여지가 있다.
- 자동 회귀 테스트는 백엔드 1,220개, 프런트엔드 186개가 통과했다. 실제 모델 호출 결과와 구분해 기록한다.
- 브라우저 버튼 클릭, 다중 사용자 부하 한계, 20개 메시지를 넘는 장기 대화와 모든 여행 조건을 전수 검증하지 않았다.
- 이번 결과는 현재 버전 평가다. 과거 low와 다른 소스·프롬프트를 사용하므로 모델 추론 수준만의 효과로 비교하지 않는다.
- 우선 기본 답변 보존과 자연어 조건 처리의 결함을 고친 뒤 같은 입력으로 재평가하는 것이 적절하다.
