# 0001. 대화 Agent 기준선 평가 (gpt-6-luna, 요청 8개 × 3번)

이전 실험: 없음

## 목적
- 대화 Agent(`/chat`)가 만든 일정이 요청 조건과 도구 결과에 맞는지 같은 기준으로 잰다.
- 이후 작업(접근성 데이터 보강, 운영시간 연결, 지시문 변경)과 비교할 기준선을 남긴다.

## 설정
- 커밋: `e71041e` (`dev`, 2026-11-11) + `run_chat_agent`의 `messages` 반환
- 모델: `gpt-6-luna`, Responses API, 생각 강도 low
- 기준 날짜: 2026-11-11 고정, 여행일 2026-11-20
- 평가 요청: [`scripts/eval_cases/chat_cases.json`](../../scripts/eval_cases/chat_cases.json) 8개, 요청당 3번 (총 24번)

## 실험 방법
- 실행: `python -B -m scripts.evaluate_chat_agent --label baseline` (서버 없이 Agent 직접 호출)
- 필수 조건(코드 채점, 실행 1번은 모두 통과해야 통과)

| ID | 항목 | 통과 기준 |
| --- | --- | --- |
| H1 | 일정 생성 여부 | 일정 전달 여부가 기대 결과와 같음 (날짜·일수·이동수단이 빈 일정은 전달 안 됨) |
| H2 | 일차 수 | 1일차부터 요청 일수까지 순서대로 |
| H3 | 시간 | 시간 검사 오류 0개 (C08은 10:00~15:00 범위 포함) |
| H4 | DB 장소 | 방문 장소 `place_id`가 모두 DB에 있음 |
| H5 | 검색 근거 | 방문 장소가 모두 이번 실행의 `search_places` 결과에 있음 |
| H6 | 이동시간 근거 | 이동시간이 이번 실행 도구 결과와 같음 (초→분 올림, ±1분) |
| H7 | 이동수단 | 요청과 다른 이동 도구 호출 없음 |
| H8 | 조건 유지 | 요청한 보조기구·필수 시설이 답변 options에서 빠지지 않음 |

- 품질 채점표 R1~R6(사람 채점), 과정 지표, 데이터 충족도는 기록만 한다.
- 산출물: `outputs/chat_eval/20261111-1209_baseline/` (`runs.jsonl`, `summary.csv`, `report.md`)

## 결과 채택 기준
- 24번 모두 기록이 남으면 기준선으로 채택한다. 실행 오류는 실패한 실행으로 센다.
- 2026-11-11 0002 결과 확인 후 변경: 처음 기준은 "모든 실행이 오류 없이 기록됨"이었다. AI 답 형식 오류도 실제로 일어나는 실패라 측정 결과로 본다 (사용자 결정).
- 기준선 측정이라 점수 기준은 두지 않는다.

## 한계
- 요청 8개 × 3번이라 요청별 통과 횟수의 변동이 크다.
- 품질 채점표 R1~R6은 아직 채점하지 않았다.
- 하루 방문 1곳 이하 일정은 실패로 보지 않는다 (11 / 17일, 기록용 지표).
- C05·C06의 기대 결과(일정)는 지시문의 "숙소 위치가 필요하면 질문한다" 규칙과 맞지 않을 수 있다.
- 데이터 충족도는 DB 칸 기준이며, Agent가 장소 설명 글로 확인한 접근성은 반영하지 않는다.
- 카카오 이동시간은 조회 시점마다 달라 실행 간 이동시간을 직접 비교할 수 없다.
