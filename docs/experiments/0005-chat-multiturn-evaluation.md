## 2. 응답 내용 검토

아래 M03은 계산 피드백을 추가한 뒤의 마지막 실행입니다.
호출 수와 시간은 각 단계 응답의 기록이며, 한 단계의 Agent 실행은 여러 모델·도구 호출을 포함할 수 있습니다.

| 사례 | 결과 | 모델·도구 호출: 첫 단계 → 다음 단계 | 처리시간: 첫 단계 → 다음 단계 |
|---|---|---|---|
| M01 | `message` → `plan`, 두 단계 자동 통과 | 2·1 → 4·4 | 7.1초 → 18.4초 |
| M02 | `plan` → `plan`, 두 단계 자동 통과 | 5·5 → 3·4 | 22.0초 → 13.5초 |
| M03 | `plan` → `plan`, 두 단계 자동 통과 | 5·7 → 5·9 | 28.0초 → 34.5초 |

각 응답은 HTTP 200이며 모두 첫 Agent 시도에서 반환됐습니다.
M01은 미정 날짜·기간·이동수단을 유지한 질문 뒤, 후속 답변으로 당일 자동차 일정을 만들었습니다.
M02는 같은 한라수목원 방문을 60분에서 90분으로 바꾸고 조건을 유지하며 왕복 경로를 새로 조회했습니다.
M03은 실제 검색한 첫 숙소 후보의 ID·이름·주소·좌표를 선택 옵션과 최종 응답에 동일하게 반영했습니다.
두 관광지의 60분 방문과 나머지 여행 조건을 유지했습니다.

| M03의 추가·유지 이동 | 시간표 |
|---|---|
| 한라수목원 → 선택 숙소 | 1일차 10:19~10:22, 3분입니다. |
| 선택 숙소 → 제주국립박물관 | 2일차 09:00~09:25, 25분입니다. |
| 박물관 → 제주빅데이터센터 | 2일차 10:25~10:48, 23분입니다. |

M03의 시간표 차이와 소요시간, 초 단위 조회값의 분 단위 올림값이 모두 일치했습니다.
일정의 경로 ID와 반환된 지도 경로도 일치했습니다.

별도 숙소 이름·주소 검색은 `not_found`였고 응답에 이 안내가 남았습니다.
앞서 조회한 주변 숙소 후보와 선택 좌표는 일치하므로 후보 연결 실패와 구분합니다.
이는 설명 품질·추가 조회의 관찰사항이며 이번 작업에서 수정하지 않았습니다.
가격·잔여 객실·접근성이나 예약 가능 여부를 검증한 결과는 아닙니다.

## 3. 발견한 오류와 보완

| 실행·관찰 | 처리와 확인 |
|---|---|
| 최초 M03의 귀환 설명 | 답변은 11:00 센터 귀환, 시간표는 11:24 도착이었습니다. 당시 자동 검사는 두 단계 모두 통과했습니다. |
| 귀환 표현 보완 | 출발지를 가리키는 ‘돌아옵니다’ 등의 명시적 시각을 공통 검사에 추가했습니다. 최초 응답 재채점에서 첫 단계만 `reply_consistency=False`로 검출했습니다. |
| 다음 M03의 시간 계산 | 숙소 선택 단계에서 `11:27~11:50`에 24분을 적었고, 자동 재시도도 같은 오류를 반복해 HTTP 502 `plan_validation_failed`가 반환됐습니다. |
| 계산 피드백 보완 | 현재 시각·표기 소요시간과 `11:27 + 24분 = 11:51`의 계산 근거를 추가했습니다. 시간표 자동 수정, 검증 허용 범위와 재시도 횟수는 바꾸지 않았습니다. |
| 마지막 M03 | 두 단계 모두 통과했습니다. 두 단계 모두 첫 시도여서 추가한 재시도 피드백의 실제 효과는 확인하지 못했습니다. |

실제 자동 재시도 후 실패한 사례는 관찰했으나, 재시도로 수정에 성공한 실제 사례는 관찰하지 않았습니다.
원래 실패 기록은 그대로 보존했습니다.
