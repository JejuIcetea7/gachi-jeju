# 0007. 방문 순서 후보와 고정 순서 검증 (자동차 당일)

검증일: 2026-11-17

실행 후 정리한 기록입니다. 판정 항목은 실행 전에 사례 파일의 `review_points`에 작성했습니다.
이전 기록은 [0006](0006-lodging-selection-consistency.md)입니다.

────────────────────────────────────────

## 1. 목적

직선거리 순서 후보를 실제 Agent가 사용하는지, 사용자 고정 순서를 유지하는지 확인합니다.
자동 통과와 별도로 방문 장소·체류시간·도구 기록·최종 지도 경로를 검토합니다.

────────────────────────────────────────

## 2. 설정

| 항목 | 조건 |
|---|---|
| 코드·모델 | `feat/route-efficiency`, 기준 커밋 `a1e0b12`에 작업 변경이 있는 상태이며 `gpt-6-luna`·reasoning effort `low`입니다. |
| 날짜 | 해석 기준일은 2026-11-17, 여행일은 2026-11-20입니다. 실제 교통 조회는 11월 17일에 수행했습니다. |
| 여행 조건 | 센터 출발·귀환, 자동차, 09:00~19:00, 보조기구·필수 시설 조건 없음입니다. |
| 방문 장소 | 한림공원(P001), 함덕서우봉해변(P038), 협재해수욕장(P010)을 각각 한 번씩 60분 방문합니다. |
| 사례 파일 | [chat_route_efficiency_cases.json](../../scripts/eval_cases/chat_route_efficiency_cases.json)에 순서 자유 R01과 순서 고정 R02를 정의했습니다. |

────────────────────────────────────────

## 3. 실험 방법

기존 최종 응답 평가 CLI로 각 사례를 한 번씩 독립 실행하고 저장된 API 응답과 도구 기록을 검토했습니다.
결과 폴더의 공통 위치는 `outputs/chat_eval/api/`입니다.

| 사례 | 결과 폴더 |
|---|---|
| R01 | `20261117-154708-559262_api-route-efficiency-check` |
| R02 | `20261117-155040-515918_api-route-fixed-order-check` |

브라우저에서는 백엔드를 재시작한 뒤 새 여행의 순서 자유 요청으로 지도와 일정표를 확인받았습니다.
화면 확인은 사용자 답변 기준이며 해당 브라우저 실행의 별도 API 기록은 수집하지 않았습니다.

## 4. 결과 채택 기준

| 기준 | 확인 항목 |
|---|---|
| 순서 자유 | 실제 순서 도구를 호출하며 한림공원·협재해수욕장 사이에 함덕서우봉해변을 끼워 넣지 않습니다. |
| 순서 고정 | 한림공원→함덕서우봉해변→협재해수욕장을 유지합니다. 순서 도구 사용 시 고정 장소를 보호합니다. |
| 조건 유지 | 세 장소를 각각 한 번씩 60분 방문하고 센터 출발·귀환과 09:00~19:00 범위를 지킵니다. |
| 경로 연결 | 최종 이동의 경로 ID가 이번 실행의 조회와 반환된 지도 경로에 일치합니다. |

## 5. 결과

| 항목 | R01 순서 자유 | R02 사용자 순서 고정 |
|---|---|---|
| 응답 | HTTP 200·Agent 1회·자동 통과 True | HTTP 200·Agent 1회·자동 통과 True |
| 방문 순서 | 한림공원→협재해수욕장→함덕서우봉해변 | 한림공원→함덕서우봉해변→협재해수욕장 |
| 순서 도구 | 2회. 첫 비교에서 순서를 바꾸고 두 번째 비교에서는 같은 결과를 반환했습니다. | 1회. 세 장소 모두 `fixed_place_ids`로 전달해 순서를 유지했습니다. |
| 방문·지도 | 세 장소 각 60분, 이동 4개의 지도 경로 ID 일치 | 세 장소 각 60분, 이동 4개의 지도 경로 ID 일치 |

아래 값은 최종 일정에서 사용한 자동차 경로 네 개의 조회값 합계입니다.

| 항목 | R01 | R02 |
|---|---:|---:|
| 조회 거리 | 115,489m | 193,149m |
| 조회 소요시간 | 9,820초(약 164분) | 15,904초(약 265분) |

두 실행에서 관찰한 차이는 77,660m·6,084초(약 101분)입니다.
R02는 사용자가 긴 동선을 고정한 대조 사례이며 수정 전 모델의 결과가 아닙니다.
조회 시각이 달라 이 차이를 동일 교통 조건의 비교나 보장되는 절감량으로 사용하지 않습니다.
R01 도구의 직선거리 합 150,857m→89,718m도 실제 도로 거리와 구분합니다.

Python 전체 950개가 통과했고 `git diff --check`에 출력이 없었습니다.
브라우저에서 가까운 두 장소의 연속 배치, 세 장소 각 60분, 센터 출발·귀환과 지도·일정표 표시를 사용자에게 확인받았습니다.
내용을 검토했지만 저장 결과의 검토 필요 플래그는 변경하지 않았습니다.

## 6. 한계

직선거리 후보를 제안하며 실제 최단 이동시간·버스 환승·휠체어 통행의 최적성을 보장하지 않습니다.
실제 검증은 자동차 당일 두 사례와 순서 자유 화면입니다. 여러 날의 권역 배치·다른 이동수단·숙소 변경 후 재정렬은 실제 실행으로 확인하지 않았습니다.
R01 귀환 조회 1,922초의 분 올림값은 33분이지만 일정에는 32분이 반영돼 기존 ±1분 허용 범위로 통과했습니다.
R01은 순서 도구 2회·자동차 도구 7회를 호출했으므로 외부 호출량 감소의 근거로 사용하지 않습니다.
반복 성공률과 모든 요청에서의 도구 사용 여부는 확인하지 않았으며 서버가 방문 순서를 강제로 재배치하지 않습니다.
