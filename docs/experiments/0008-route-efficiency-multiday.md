# 0008. 여러 날의 동선과 숙소 변경 검증

검증일: 2026-11-17~18

자동차 1박 2일의 권역 배치, 실제 숙소 후보 선택과 채팅으로 요청한 숙소 변경을 확인한 기록입니다.
자동 판정, 저장 응답 검토와 사용자 화면 확인을 구분합니다.
이전 자동차 당일 검증은 [0007](0007-route-efficiency.md)입니다.

숙소 선택·변경 이후에는 방문일·장소·횟수·각 60분과 접근 조건을 유지해야 합니다.
직선거리 후보와 실제 이동 조회는 별도로 검토합니다.

## 2. 발견한 문제와 보완

| 문제 | 처리 |
|---|---|
| 경로 ID 오타로 재생성·시간 초과 | 이번 시도의 검색·상세 조회와 양 끝점·이동수단·시간이 일치하는 미사용 경로가 하나일 때만 누락·미등록 ID를 보완합니다. 이미 등록된 ID는 덮어쓰지 않습니다. |
| 가까운 두 관광지의 좌표와 이동 방향 혼동 | 대화형 이동 도구에 `place:DB장소ID`, `departure`, `stay:N`, 이번 위치 조회의 `found:...` 참조를 전달하고 서버가 확인된 좌표로 변환합니다. |
| 재생성에서 관광지 재조회 생략 | 이번 시도의 성공한 상세 조회를 관광지 이동·순서 비교의 선행 조건으로 두고 최종 방문의 상세 조회 근거도 검사합니다. |
| 새 숙소 이동은 맞지만 순서 비교는 이전 숙소 사용 | 하루 전체 비교를 수행한 경우 최종 출발지·숙소·귀환 위치에 맞는 성공 근거가 있는지 대조합니다. 새 숙소의 위치 참조를 순서 비교에도 사용하도록 지시합니다. |
| 박물관의 확인된 화장실까지 unknown으로 설명 | 장소별 Y·N·unknown과 현장 기록을 구분하도록 지시하고 후속 응답을 검토했습니다. 모든 자연어 시설 설명을 자동 검증하는 기능은 아닙니다. |

기존 최대 한 번의 재생성, 서버 150초 예산, 이동 끝점 100m 검사와 시간 허용 기준을 유지했습니다.
모호한 경로 후보를 임의 선택하거나 이미 유효한 경로 ID를 다른 방향으로 교체하지 않습니다.

## 3. 확인 결과

**RM01 두 단계**

최종 대표 실행은 두 단계 모두 첫 Agent 시도에서 HTTP 200과 자동 통과를 반환했습니다.

| 단계 | 관찰 |
|---|---|
| T01 숙소 미정 | 44.742초, 모델 5회, 장소 검색 4회·상세 4회·순서 비교 2회·자동차 조회 4회입니다. 1일차 박물관→함덕, 2일차 한림→협재로 배치했습니다. 미정 숙소 도착·출발 이동은 없었습니다. |
| T02 숙소 후보 선택 | 33.976초, 모델 4회, 장소 검색 4회·상세 4회·순서 비교 2회·자동차 조회 6회입니다. 검색 후보 '박하제주'의 이름·주소·좌표·외부 식별값을 첫 숙박일에 반영했습니다. |

T02에서는 선택한 숙소를 첫날 순서 비교의 도착과 다음 날 순서 비교의 출발에 사용했습니다.
2일차는 협재→한림으로 조정됐으며 네 방문의 일차·횟수·각 60분은 유지됐습니다.
직선거리 감소 39.2m는 실제 이동시간 절감량으로 해석하지 않습니다.
최종 이동과 지도 경로 ID는 T01 네 개, T02 여섯 개가 각각 일치했습니다.

**제주신라호텔로 변경**

초기 변경 진단은 HTTP 200이었지만 순서 비교에 이전 숙소를 사용했습니다.
보완 후 진단은 42.162초, 첫 Agent 시도, 형식 오류 기록 0건입니다.
모델 8회, 장소 검색 4회·상세 4회·위치 검색 1회·순서 비교 4회·자동차 조회 6회가 기록됐습니다.

| 일차 | 변경 후 최종 동선 |
|---|---|
| 1일차 | 센터→함덕→박물관→제주신라호텔 |
| 2일차 | 제주신라호텔→한림→협재→센터 |

`find_location(refresh=true)`의 새 호텔 좌표를 최종 숙소, 실제 이동과 두 날짜의 순서 비교에 사용했습니다.
순서 비교에는 이전 숙소를 사용한 초기 비교 한 건과 선행 상세 조회를 요구한 응답 한 건도 포함됩니다.
이후 두 날짜 모두 새 호텔 위치로 성공한 비교를 수행한 것을 확인했습니다.
직선거리 후보의 감소량은 각각 2,070.2m·240.1m이며 실제 도로 거리·시간 절감의 비교 결과가 아닙니다.

네 장소의 방문일과 각 60분, 휠체어·장애인 화장실 조건을 유지했습니다.
화장실은 박물관 Y, 나머지 세 곳 unknown으로 설명하고 전체 휠체어 동선을 보장하지 않았습니다.
최종 여섯 이동의 ID와 반환된 지도 경로도 일치했습니다.
2일차 한림→협재 이동에서는 Agent가 작성한 미등록 ID를 이번 시도의 유일한 경로 ID로 보완한 것을 확인했습니다.
시간표·이동수단을 바꾸거나 Agent를 추가 호출하지 않았습니다.
새 위치 조회가 제공하지 않은 외부 식별값과 지도 URL은 null로 두었습니다.

**자동 검사와 화면**

신규 검사 68개를 추가한 뒤 사용자 실행에서 Python 전체 1,018개와 `git diff --check`가 통과했습니다.
신규 검사는 경로 ID 보완 20개, 위치 참조 20개, 현재 상세 근거 14개, 순서 비교 경계 14개입니다.
이후 추가한 형식 오류 진단 로그는 별도 오프라인 7항목과 실제 브라우저 오류 로그로 확인했습니다.

브라우저에서는 기존 당일 일정에 숙박·다음 날 이동을 요구한 뒤 형식 오류가 발생했습니다.
화면의 출발일과 마지막 날이 같았으며, 서버에는 '숙박일은 여행 마지막 날보다 앞서야 합니다'라는 검증 오류가 기록됐습니다.
모델이 반환한 전체 실패 응답은 확보하지 않아 당시 여행 일수와 숙박일의 정확한 반환값은 확정하지 않았습니다.
새 여행에서 1박 2일을 먼저 생성한 뒤 숙소 선택·제주신라호텔 변경과 지도·일정 갱신을 사용자에게 확인받았습니다.
화면 확인은 사용자 답변 기준이며 별도의 브라우저 HTTP 기록은 수집하지 않았습니다.

## 5. 재채점과 원본 보존

RM01 재채점의 `runs.jsonl`과 `scores.jsonl`은 원본과 바이트 단위로 같았습니다.
원본 결과 파일 다섯 개의 SHA-256 검사값도 유지됐습니다.

저장된 정상 T02 응답에 변경 문장을 이어 별도의 실제 `/chat` 요청으로 실행한 기록입니다.
추가 진단의 응답·조회 기록과 원본 보존은 별도로 확인했습니다.

| 범위 | 한계 |
|---|---|
| 최적성 | 날짜별 직선거리 비교와 실제 이동 조회를 확인했습니다. 여행 전체의 최단 이동시간·숙소 최적 위치·휠체어 통행의 최적성을 보장하지 않습니다. |
