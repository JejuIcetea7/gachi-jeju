### 추출과 연결 방법

- HWP는 kordoc `convert_to_hwpx`로 변환했다. 변환본의 이미지 파일과 본문에서 사용하는 이미지 참조를 연결했다.
- 변환본에는 이미지 파일 2,018개가 있었다. 원본 HWP의 이미지 항목 2,068개와 내용 검사값(SHA-256)을 대조한 결과, 50개 항목이 변환본에 포함되지 않았다. 이 항목은 원본 컨테이너에서 보충 추출해 보존했으며 시설·설명은 미확인으로 남겼다. `sources[].extraction_method`로 `kordoc_hwpx`와 `original_hwp_supplement`를 구분한다.
- HWP 원본 이미지 항목 2,068개 모두 통합 사진에 같은 파일 내용으로 보존됐음을 검증했다. 같은 이미지가 문서에 여러 번 배치된 경우에는 각 배치의 설명·위치를 남겼다.
- 일반정보 HWP는 표의 실제 행·열과 셀 병합 범위를 읽는다. 바로 아래 설명 셀의 열 범위가 사진 셀과 같을 때 개별 설명으로 연결한다. 병합된 공통 설명은 특정 사진 하나의 설명으로 단정하지 않고 `[표 공통 설명]`으로 구분한다.
- 사진 아래 개별 설명이 없어도 같은 시설 표의 정보는 `[시설 공통 정보]`와 원본 셀 위치로 보존한다. 중첩표는 부모 표와 분리해 연결한다.
- 허브 HWP는 그림 번호·원본 파일명이 포함된 캡션과 실제 이미지 참조를 함께 보존한다. 그림 번호를 추출 순서나 이미지 파일 번호와 동일하다고 가정하지 않는다.
- 소제목 아래 여러 사진에 공통으로 적힌 글은 `[절 공통 설명]`으로 기록하고 다음 소제목에서 범위를 끊는다. 사진이 있는 문단 자체의 설명은 `[사진 문단]`으로 남긴다. 명확한 소제목 없이 주변에 있는 글은 출처의 `context`에만 보존하고 개별 설명으로 배정하지 않는다.
- 드라이브는 원본 `hub_*` 폴더와 `image_file`을 함께 대조해 기존 지점 1,722건에 연결했다. 정리된 지점 설명뿐 아니라 원본 CSV의 사진 파일명·아이디·레코드 번호·원본 필드도 `sources`에 보존했다. 원본의 사진 행과 설명 행이 합쳐진 경우 설명은 기존 `place_spots.csv`를 근거로 유지한다.
- CSV에 없는 드라이브 사진 61장은 폴더로 장소만 연결하고 시설·설명은 추정하지 않았다.

### CSV 항목

UTF-8 BOM 인코딩으로 저장한다. 여러 값을 담는 컬럼은 배열 형태의 JSON 문자열이며, CSV 읽기 후 JSON으로 해석한다.

| 컬럼 | 의미 |
| --- | --- |
| `photo_id` | 사진 고유 ID. 예: `P001_0001` |
| `place_id` | 파일을 보관한 대표 장소 ID |
| `place_ids` | 모든 관련 장소 ID 목록. 장소별 사진 조회는 이 목록을 기준으로 한다. |
| `image_path` | 프로젝트 기준 통합 사진 상대 경로 |
| `spot_order` | 확인된 기존 지점 순서 목록. 사진 ID의 번호와 별개 |
| `spot_name` | 연결된 시설·지점 또는 문서 소제목 |
| `description` | 출처별 설명을 합친 글. 설명이 없으면 `설명 없음` |
| `source_type` | `drive`, `general_hwp`, `hub_hwp` 중 해당 출처 목록 |
| `source_file` | 원본 파일 경로 목록 |
| `original_image_ref` | 원본 그림·파일 참조 목록 |
| `description_source_file` | 설명을 읽은 파일 목록 |
| `description_source_ref` | 설명의 표 셀·문단·지점 위치 목록 |
| `mapping_status` | 출처별 연결 상태 목록 |
| `sha256` | 파일 내용 검사·완전 중복 판별 값 |
| `image_format` | 실제 파일 형식. JPEG·PNG·BMP·MPO |
| `width`, `height` | 이미지의 가로·세로 픽셀 |
| `size_bytes` | 파일 크기 |
| `sources` | 출처별 장소·시설·설명·원본 번호·원본 CSV 행·문서 위치·공통 문맥을 모두 보존한 JSON 목록 |

`spot_order`와 `spot_name` 같은 요약 컬럼만으로 출처별 관계를 복원하지 않는다.
정확한 사진–장소–시설–설명 연결은 `sources`의 같은 항목 안에서 읽는다.

| 연결 상태 | 근거 |
| --- | --- |
| `csv_filename` | 같은 원본 폴더의 사진 파일명으로 기존 지점과 연결 |
| `table_caption` | 열 범위가 일치하는 바로 아래 표 셀의 설명 |
| `table_context` | 동일 표의 공통 설명·시설 정보 |
| `picture_caption` | 사진 개체에 직접 붙은 설명 캡션. 원본 파일명만인 캡션은 설명으로 세지 않음 |
| `picture_paragraph` | 사진을 포함한 문단의 설명 |
| `section_context` | 명확한 소제목 아래의 공통 설명 |
| `unconfirmed` | 장소·출처는 보존했으나 시설·설명을 확정하지 못함 |

### 실행 중 추가로 정한 사항

1. **HWP 변환 누락 보완:** kordoc를 주 경로로 사용하되, 원본 내용 대조에서 빠진 50개 이미지 항목은 원본에서 보충 추출하고 미확인으로 보존했다.
2. **여러 장소의 동일 파일:** 파일·CSV 행은 하나만 두고 `place_ids`와 `sources`에 모든 장소를 남겼다. 첫 수집 출처의 장소 폴더에 보관한다. 여러 장소에 연결된 고유 파일은 14개이며, 같은 시설이라는 뜻으로 해석하지 않는다.
3. **원본 번호와 새 번호 구분:** 사진 ID 번호는 정렬된 출처 경로·문서 위치를 기준으로 부여한 관리 번호다. 관람 순서나 원본 그림 번호가 아니다. 갱신 시에는 내용 검사값으로 기존 ID·경로를 찾아 유지하고 새 사진만 다음 번호를 부여한다.
4. **실제 형식 유지:** JPG·PNG·BMP와 JPG 안의 MPO 형식을 그대로 보존했다. 크기 변경, 재압축, 회전, WebP 변환은 하지 않았다. 안내 그림이나 로고로 보이는 파일도 임의로 삭제하지 않았다.
5. **공통 설명의 범위 표시:** 개별 사진 설명과 표·절의 공통 설명을 구분하는 표시를 넣었다. 설명은 원문을 보존하고 AI로 새 설명을 만들지 않았다.
6. **근거 보존용 상세 컬럼:** 단일 CSV를 유지하면서 복수의 출처·설명 관계를 잃지 않도록 배열과 `sources` JSON 컬럼을 추가했다. 파일 내용 검사값·해상도·용량도 함께 기록했다.
7. **시설 미확인 표현:** 확인되지 않은 시설명·지점 순서는 빈 값으로 두고 `mapping_status`에 `unconfirmed`를 기록했다. 설명이 없는 경우는 합의대로 `설명 없음`을 사용했다.
8. **원본 CSV 추가 보관:** 드라이브 사진의 원래 아이디·행을 추적하고 현재 워크트리에서 다시 읽을 수 있도록, 다른 워크트리의 연결 원본 CSV 51개를 기존 경로대로 복사했다. 원본과 내용이 같음을 검증했다.
9. **중간 산출물 분리:** 변환 HWPX·입력 명세·검증 기록은 `outputs/place_photos/`에 두었다. 원본과 통합 이미지·중간 파일은 Git에서 제외하고 목록 CSV·스크립트·테스트·문서는 Git 관리 대상으로 두었다.
10. **스크립트와 검증 의존성:** 정리 절차를 `scripts/build_place_photos.py`에 두고 이미지 해상도·형식 검증에 사용한 `Pillow==12.0.0`을 의존성에 추가했다. 기본 실행은 기존 결과의 덮어쓰기를 막고, 명시적인 `--refresh-metadata` 실행에서만 기존 ID를 유지한 갱신을 허용한다.
11. **CSV 인코딩:** 한글을 표 계산 프로그램에서도 읽기 쉽도록 UTF-8 BOM을 사용했다. 모든 경로는 프로젝트 기준 상대 경로로 기록했다.

### 실행과 검증

HWP별 `place_id`, `source_type`, `source_file`, `converted_path`를 담은
`outputs/place_photos/hwp_sources.json`과 해당 HWPX 변환본을 먼저 준비한다.
원본 HWP에서 HWPX를 만드는 단계는 kordoc 도구로 수행한다.

```sh
python -B scripts/build_place_photos.py
# 이미 생성한 결과의 ID를 유지하면서 설명·출처 및 추가 사진을 갱신할 때
python -B scripts/build_place_photos.py --refresh-metadata
python -B -m unittest discover -s tests -p test_place_photos.py -v
```

- 자동 테스트 9개 통과: 표 열 일치, 병합 셀의 공통 설명 분리, 다음 사진과의 혼동 방지, 원본 그림 번호 보존, 소제목 경계, 중첩표 분리, 사진 문단 설명 보존 등을 확인했다.
- 이미지 파일 3,834개 모두 정상적으로 열어 형식·해상도를 읽었고, 통합 후 내용 검사값이 일치했다.
- 사진 ID·파일 내용의 중복, 실제 파일 목록과 CSV 행의 일치, 등록 장소 ID 참조를 검증했다.
- 드라이브 원본 1,783개와 CSV 파일명 참조 1,722건을 모두 보존했다.
- HWP 원본 이미지 항목 2,068개가 통합 결과에 빠짐없이 보존됐음을 검증했다.
- 자세한 실행 결과는 `outputs/place_photos/verification.json`에 있다.
- 기존 교통·대화 기능은 변경하지 않았으며, 이번에는 사진 정리 관련 테스트만 실행했다.

## 남은 범위

- 미확인 시설·설명 연결에 대한 개별 검토. 원문 배치에 근거해 자동 연결한 항목도 전수 시각 검토한 것은 아니다.
- 같은 장면이지만 크기·압축이 다른 사진의 비교. 이번에는 파일 내용이 완전히 같은 경우만 중복 처리했다.
- 웹용 이미지 가공은 2026-11-13 완료했다. 기준과 결과는 [웹용 사진 가공](place-photo-web-processing.md)에 기록했다.
- 클라우드 업로드, Agent 조회 도구 및 화면 연결은 진행하지 않았다.
